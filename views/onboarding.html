Overview

Harbor Orders is a small Express + SQLite API for managing orders across three harbour customers: Harbor Cafe, North Dock, and Blue Pier. There is no database server — SQLite runs entirely in-process via sql.js (pure WebAssembly). 

HTTP Request
    │
    ▼
Express Router  (src/app.js)
    │  validates input, calls db.prepare().get/.all/.run()
    ▼
sql.js in-memory DB  (RAM — fast synchronous reads)
    │  every write calls persist()
    ▼
harbor.db  (disk — survives restarts)

Startup sequence: src/server.js calls initDb() which loads the WASM module, opens harbor.db from disk into memory, creates the orders table if it does not exist, and inserts three seed rows when the table is empty. Only after that promise resolves does Express begin listening.

Reads are synchronous against the in-memory copy — effectively RAM speed. Writes call persist() which serialises the whole database and writes it to disk with fs.writeFileSync. This keeps the API simple with no async transaction management.

Order status machine — one-way, no skipping, no reversal:

new → packed → shipped

The transition map is a plain object in src/app.js: { new: 'packed', packed: 'shipped' }. Any other transition returns HTTP 400.

Key files at a glance:

  • src/server.js — process entry point, loads env + starts server
  • src/app.js — Express routes, validation, status machine
  • src/db.js — sql.js wrapper, initDb(), persist()
  • src/onboarding.js — this onboarding UI + its API endpoints
  • docs/RUNBOOK.md — authoritative setup instructions
  • docs/ARCHITECTURE.md — architecture deep-dive
